## 1. Мета роботи
Основною метою цієї роботи є проведення функціонального тестування розробленої системи прогнозування навантаження серверів, виявлення дефектів, їх документування (створення bug reports), усунення знайдених помилок та проведення повторного (регресійного) тестування для підтвердження виправлень.

## 2. Завдання
1. Провести функціональне тестування ПЗ і оформити результати у вигляді таблиці, що включає тести нормальних умов, граничних умов та виняткових ситуацій.
2. Виявлені дефекти усунути та оформити у вигляді bug report.
3. Провести повторне тестування за аналогічним набором тестів.
4. Оформити окрему таблицю регресійного тестування (повторної перевірки).

## 4. Висновки
У ході виконання лабораторної роботи було проведено функціональне тестування системи прогнозування навантаження серверів. Тестування проводилося за трьома основними напрямками: перевірка нормальних умов, граничних умов та виняткових ситуацій. Результати первинного тестування (версія v.0.1.0) дозволили виявити низку дефектів, пов'язаних з UI, обробкою з'єднань WebSocket, відсутністю візуальних попереджень та помилками при отриманні великих обсягів історичних даних.

Після усунення виявлених недоліків було випущено версію v.0.1.1 та проведено регресійне тестування. Успішно виправлено:
- Помилку `exceeded maximum resolution` для Prometheus (додано динамічний step).
- Проблему з відображенням статусу WebSocket-з'єднання.
- Відсутність даних для нових вузлів (додано fall-back на 1 годину).
- Додано візуальні попередження у UI (Coverage < 80%, Upper > 100%).
- Додано CRUD операції для редагування параметра `SafeBoundary`.
- Додано автоматичний Backfill при відновленні зв'язку з Prometheus.

Незважаючи на виправлення технічних помилок, основною невирішеною проблемою залишається неадекватність ML-моделі, яка була навчена на даних з високим рівнем використання CPU (66-100%). Через це при прогнозуванні на реальних метриках з низьким навантаженням модель екстраполює дані і видає завищені показники (>90%). Для вирішення цієї проблеми у майбутньому необхідно перенавчити модель на більш релевантному наборі даних.
