# Результат функціонального тестування програми

Дата: 2026-05-13  
Проєкт: AI-система прогнозування навантаження на сервер  
Версія: v.0.2.0

---

## Опис проблеми

**Заголовок:** Відсутня підтримка прогнозування RAM - відсутня RAM-модель та RAMPercent обчислення

**Серйозність:** Висока

**Пріоритет:** Високий

**Опис дефекту:**

Система прогнозувала лише CPU usage, але не підтримувала прогнозування RAM (оперативної пам'яті). Були відсутні:
1. Окрема ML-модель для RAM forecasting
2. Поле `RAMPercent` для зберігання % використання RAM в метриках
3. Обчислення RAMPercent з даних Prometheus (RAMBytes / mem_limit * 100)
4. UI компоненти для відображення RAM прогнозів та графіків
5. Оновлення схеми БД для колонки `ram_usage_percent`

---

## Кроки відтворення

1. Відкрити Dashboard за адресою `/ui`
2. Переглянути картку вузла - відображається лише CPU
3. Перейти на сторінку Node Details
4. Спостерігати: немає окремого графіка для RAM
5. У консолі браузера: WebSocket повідомлення не містять `ram_*` полів

---

## Очікувана поведінка

1. Dashboard показує: CPU % → CPU pred | RAM % → RAM pred
2. Node Details має два окремі графіки (CPU та RAM)
3. WebSocket передає: `cpu`, `ram`, `cpu_lower`, `cpu_upper`, `ram_lower`, `ram_upper`
4. Quality Metrics показують MAE та Coverage для кожного ресурсу окремо

---

## Фактична поведінка (до виправлення)

- UI відображав лише CPU дані
- RAM використовував `RAMBytes` напряму без конвертації в %
- Не було окремої RAM-моделі
- Sparkline показував тільки CPU історію

---

## Аналіз причин

1. **ML-пайплайн** (`model/pipeline.py`): `target_resources = ['cpu_usage']` - RAM не тренувалась
2. **Domain models** (`domain/models.go`): відсутнє поле `RAMPercent`
3. **Feature Engineer** (`feature_engineer.go`): метод `PrepareVector()` використовував лише `CPUPercent`
4. **Prometheus Adapter**: не обчислював `RAMPercent` з `RAMBytes / limit`
5. **ForecasterService**: використовував одну модель замість двох
6. **UI**: шаблони `node.html` та `dashboard.html` не відображали RAM

---

## Виправлення

### 1. ML-пайплайн
```python
# model/pipeline.py
target_resources = ['cpu_usage', 'ram_usage']
```

### 2. Domain models
```go
// domain/models.go
type Metric struct {
    RAMPercent float64 `db:"ram_usage_percent"`
}
```

### 3. Feature Engineer
```go
// feature_engineer.go
func (fe *FeatureEngineer) PrepareVector(metrics []domain.Metric, isRAM bool) []float32 {
    getValue := func(m domain.Metric) float64 {
        if isRAM {
            return m.RAMPercent
        }
        return m.CPUPercent
    }
    // ...
}
```

### 4. Prometheus Adapter
```go
// prometheus.go
type MemLimiter struct {
    mu     sync.RWMutex
    limits map[string]int64
}

// RAMPercent = (RAMBytes / mem_limit) * 100
m.RAMPercent = float64(s.Value) / float64(a.limiter.Get(name)) * 100.0
```

### 5. Forecaster Service
```go
// forecaster.go
type ForecasterService struct {
    cpuModel *tflite.Predictor
    ramModel *tflite.Predictor
    cpuMeta  *domain.ModelQuality
    ramMeta  *domain.ModelQuality
}
```

### 6. UI оновлення
- Dashboard: CPU → CPU pred | RAM → RAM pred
- Node Details: два окремих графіки з live-оновленням

### 7. Схема БД
```sql
ALTER TABLE metrics ADD COLUMN ram_usage_percent REAL;
```
